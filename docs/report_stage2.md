# Отчёт по этапу 2. Интерфейс главного экрана: список задач

## Что сделано
- Модель `Task` (data class): `id`, `title`, `description`, `date`, `isDone`.
- Список задач в `RecyclerView` + `TaskAdapter` + `TaskViewHolder`, данные — временный список в коде (`SampleTasks`).
- Карточка задачи на `MaterialCardView`: индикатор «выполнена/не выполнена», название (у выполненных зачёркнуто), дата.
- `FloatingActionButton` → переход на `AddTaskActivity` через `Intent`.
- Клик по карточке → `TaskDetailActivity`, `id` передаётся через `putExtra`.
- Схема экранов: [`screens_scheme.md`](screens_scheme.md).

## Ключевые понятия
| Понятие | Что это и как использовано |
|---|---|
| **RecyclerView** | Список с переиспользованием элементов: на экране создаётся ~столько View, сколько помещается, при прокрутке уходящие за экран View заново заполняются новыми данными. В `ListView` с большими списками расходовалось бы гораздо больше памяти |
| **LayoutManager** | Определяет расположение элементов. Здесь `LinearLayoutManager` (вертикальный список); `GridLayoutManager` даст сетку — пригодится для календаря на этапе 6 |
| **Adapter** | Мост «данные → View»: `onCreateViewHolder` создаёт элемент, `onBindViewHolder` заполняет его данными, `getItemCount` сообщает размер списка |
| **ViewHolder** | Хранит ссылки на дочерние View одного элемента (`ivStatus`, `tvTaskTitle`, `tvTaskDate`) |
| **MaterialCardView** | Карточка; `cardCornerRadius` — скругление углов, `cardElevation` — высота (тень) |
| **FloatingActionButton** | Круглая кнопка главного действия; `srcCompat` задаёт иконку (векторный drawable) |
| **Intent** | «Намерение» перейти на другой экран. Явный Intent указывает класс Activity; `putExtra` кладёт в него данные, на другом экране они читаются `getLongExtra` |
| **OnClickListener** | В Kotlin пишется лямбдой `view.setOnClickListener { ... }` вместо многословного анонимного класса `object : View.OnClickListener { override fun onClick(v: View) { ... } }` — поведение то же, код короче |

## Зачем нужен ViewHolder
`findViewById` обходит дерево View и ищет элемент по id. Если вызывать его в `onBindViewHolder`, то поиск будет
выполняться для **каждого** элемента при **каждой** прокрутке — лишняя работа в самый «горячий» момент, из-за чего
список начнёт подтормаживать. ViewHolder делает этот поиск один раз при создании элемента и затем только
переиспользует сохранённые ссылки.

## Как проверить
Запустить приложение: список прокручивается; нажатие на карточку открывает детали нужной задачи; FAB открывает пустой экран;
стрелка «назад» возвращает к списку.
