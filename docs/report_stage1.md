# Отчёт по этапу 1. Настройка окружения и основы

## Что сделано
- Создан проект «Календарь задач» (Kotlin, Empty Views Activity), пакет `ru.university.taskcalendar`, minSdk 26.
- Главный экран `MainActivity` со статичным списком из 5 задач-заглушек (ConstraintLayout + вертикальный LinearLayout).
- Все тексты вынесены в `res/values/strings.xml`.
- Во всех методах жизненного цикла Activity добавлено логирование (Logcat, тег `Lifecycle`).

## Структура проекта
| Файл / папка | Назначение |
|---|---|
| `app/src/main/java/...` | Kotlin-код (Activity и т. д.) |
| `app/src/main/res/` | Ресурсы: разметка (`layout`), строки, цвета, темы, иконки |
| `AndroidManifest.xml` | Описание приложения: экраны, иконка, название, разрешения |
| `app/build.gradle.kts` | Настройки сборки модуля: `minSdk`, `targetSdk`, `compileSdk`, зависимости |
| `build.gradle.kts`, `settings.gradle.kts` | Настройки корня проекта, версии плагинов, репозитории |
| `gradle/wrapper/` | Gradle Wrapper — фиксирует версию Gradle для всех, кто собирает проект |

`minSdk` — самая старая версия Android, на которой приложение запустится (26 = Android 8.0);
`targetSdk` — версия, под которую приложение протестировано; `compileSdk` — версия API, с которой компилируется код.

## XML-атрибуты, использованные в разметке
| Атрибут | Что делает |
|---|---|
| `layout_width`, `layout_height` | Размер View. `match_parent` — на всю доступную ширину/высоту родителя; `wrap_content` — ровно по размеру содержимого; `0dp` в ConstraintLayout — «растянуть по ограничениям» |
| `id` (`@+id/tvHeader`) | Идентификатор View, по нему элемент находится в коде (`findViewById`) и в ограничениях |
| `padding` | Внутренний отступ — от границы View до его содержимого |
| `layout_margin*` | Внешний отступ — расстояние до соседних View |
| `text` (`@string/...`) | Текст элемента, взятый из ресурсов |
| `textAppearance` | Готовый стиль текста из темы (размер, шрифт, межстрочный интервал) |
| `background` | Фон элемента (здесь — скруглённая рамка `bg_task_stub`) |
| `orientation` | Направление расположения детей в LinearLayout (`vertical`/`horizontal`) |
| `layout_constraintStart_toStartOf`, `...Top_toBottomOf` и др. | Ограничения ConstraintLayout: к какой стороне какого элемента привязана данная сторона |

**Пример разницы `match_parent` и `wrap_content`:** кнопка с `layout_width="match_parent"` растянется на всю ширину
экрана, а с `wrap_content` будет ровно по ширине надписи на ней.

**Зачем ConstraintLayout:** положение элементов задаётся ограничениями относительно родителя/соседей, поэтому
не нужна глубокая вложенность (она замедляет отрисовку).

**Зачем `strings.xml`:** один источник текстов (нет дублирования), удобно переводить на другие языки
(`values-en/strings.xml`), можно подставлять параметры (`%1$d`), тексты не смешиваются с кодом.

## Жизненный цикл Activity
| Метод | Когда вызывается | Что обычно делают |
|---|---|---|
| `onCreate()` | Один раз при создании Activity | Загружают разметку (`setContentView`), находят View, настраивают начальное состояние |
| `onStart()` | Экран становится видимым | Подготовка к показу (подписки, обновление данных, которые нужны на видимом экране) |
| `onResume()` | Экран на переднем плане и доступен для ввода | Запуск анимаций, обновление данных, которые должны быть актуальны всегда |
| `onPause()` | Экран теряет фокус (поверх открылось другое окно/диалог) | Быстро сохранить несохранённое, приостановить анимации |
| `onStop()` | Экран полностью невидим (перешли на другой экран, свернули приложение) | Освободить ресурсы, которые не нужны в фоне |
| `onDestroy()` | Activity уничтожается (закрыта пользователем или пересоздаётся при повороте экрана) | Финальная очистка ресурсов |

Порядок при запуске: `onCreate → onStart → onResume`. При сворачивании: `onPause → onStop`.
При возврате: `onStart → onResume`. При закрытии: `onPause → onStop → onDestroy`.

## Основы Kotlin, использованные в коде
- `val` — неизменяемая ссылка (как `final`), `var` — изменяемая. `val` рекомендуют по умолчанию: код предсказуемее,
  меньше случайных изменений, безопаснее при работе с несколькими потоками.
- Null safety: `String` не может быть `null`, `String?` — может. `note?.length` вернёт `null`, если `note == null`
  (безопасный вызов), а `?: 0` подставит значение по умолчанию (оператор elvis).

## Как проверить
1. Открыть проект в Android Studio, дождаться синхронизации Gradle.
2. Запустить на эмуляторе (AVD) или физическом устройстве.
3. В Logcat отфильтровать по тегу `Lifecycle`, свернуть/развернуть приложение, повернуть экран — наблюдать вызовы методов.
